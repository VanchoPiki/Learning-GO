# Урок: Интерфейсы и «Утиная типизация»

> **Правило утиной типизации:**
> *"Если нечто плавает как утка, крякает как утка и ходит как утка — то компилятор считает, что **это утка**!"*

В Go **нет ключевого слова `implements`**.
Ты просто объявляешь интерфейс (список методов). Если какая-то твоя структура имеет эти методы — она **автоматически** считается реализацией этого интерфейса. Без лишних слов.

---

## 1. Что такое интерфейс?

**Интерфейс** — это контракт. Он говорит, **ЧТО** объект умеет делать, но не говорит, **КАК** он это делает.

Давай представим платежную систему для нашего бота:

```go
// Контракт: любой, кто хочет считаться "Плательщиком" (Payer),
// ДОЛЖЕН иметь метод Pay(amount float64) bool
type Payer interface {
    Pay(amount float64) bool
}
```

---

## 2. Неявная реализация (Магия в действии)

Давай создадим два совершенно разных кошелька: `BitcoinWallet` и `CreditCard`:

```go
package main

import "fmt"

// 1. Интерфейс (Контракт)
type Payer interface {
    Pay(amount float64) bool
}

// 2. Первая структура: Биткоин-кошелек
type BitcoinWallet struct {
    BTCBalance float64
}

// Реализуем метод Pay для Bitcoin (просто пишем метод, никакого слова implements!)
func (b *BitcoinWallet) Pay(amount float64) bool {
    if b.BTCBalance < amount {
        fmt.Println("BTC: Недостаточно биткоинов!")
        return false
    }
    b.BTCBalance -= amount
    fmt.Printf("BTC: Успешно оплачено %.4f BTC\n", amount)
    return true
}

// 3. Вторая структура: Обычная банковская карта
type CreditCard struct {
    CardNumber string
    Limit      float64
}

// Реализуем метод Pay для карты
func (c *CreditCard) Pay(amount float64) bool {
    if c.Limit < amount {
        fmt.Println("Банк: Превышен лимит по карте!")
        return false
    }
    c.Limit -= amount
    fmt.Printf("Банк: Оплачено картой %s на сумму %.2f руб.\n", c.CardNumber, amount)
    return true
}
```

**Что сейчас произошло?**
И `BitcoinWallet`, и `CreditCard` имеют метод `Pay(amount float64) bool`.
Это значит, что они **оба автоматически стали `Payer`**!

---

## 3. Полиморфизм: Зачем это нужно?

А вот ради чего всё затевалось. Мы можем написать **ОДНУ универсальную функцию покупки**, которая принимает интерфейс `Payer`.

Ей абсолютно всё равно, чем платит пользователь — биткоинами, картой или фантиками. Главное, чтобы у объекта был метод `Pay`!

```go
// Функция принимает ЛЮБОГО, кто удовлетворяет интерфейсу Payer
func BuyCourse(p Payer, price float64) {
    fmt.Println("Попытка провести оплату...")
    p.Pay(price) // Вызывается метод Pay той структуры, которую передали!
}

func main() {
    myBTC := &BitcoinWallet{BTCBalance: 1.5}
    myCard := &CreditCard{CardNumber: "4400...1234", Limit: 5000.0}

    // Передаем разные структуры в одну и ту же функцию:
    BuyCourse(myBTC, 0.2)   // Сработает логика биткоина!
    BuyCourse(myCard, 2000) // Сработает логика банковской карты!
}
```

## 4. Срез интерфейсов (Коллекция разных объектов)

Вспомни: в один срез `[]int` можно класть только числа, а в `[]string` — только строки.
**Но в срез интерфейсов можно класть разные структуры!**

```go
func main() {
    myBTC := &BitcoinWallet{BTCBalance: 1.5}
    myCard := &CreditCard{CardNumber: "4400...1234", Limit: 5000.0}

    // Срез содержит разные типы данных, объединенные одним интерфейсом:
    paymentMethods := []Payer{myBTC, myCard}

    // Списываем по 100 условных единиц со всех способов оплаты:
    for _, method := range paymentMethods {
        method.Pay(100)
    }
}
```
