В большинстве языков (C++, Java, Python) есть **наследование**:
* Ты создаешь класс `Animal`, от него наследуешь `Dog`, от него `PoliceDog`, от него `CyborgPoliceDog`...
* Спустя полгода код превращается в «спагетти», где изменение одной строчки в `Animal` ломает половину проекта.

В Go создатели сказали: **«Никакого наследования!»**.
Вместо этого Go использует подход: **Композиция (Composition)** и **Встраивание (Embedding)**.

> Принцип Go: объект определяется не тем, *кто его родитель*, а тем, **из каких деталей он собран** (как конструктор LEGO).

---

# Урок: Встраивание структур (Embedding)

**Встраивание** — это когда ты кладешь одну структуру внутрь другой, **не давая ей имени поля**.

Благодаря этому поля и методы внутренней структуры **автоматически «всплывают» (продвигаются)** наружу, и к ним можно обращаться напрямую!

---

## 1. Сравнение: Обычная вложенность vs Встраивание

Посмотри на разницу в объявлении:

```go
type Wallet struct {
    Balance float64
}

// 1. Обычная вложенность (мы это уже делали):
type RegularUser struct {
    Wallet Wallet // Поле имеет имя 'Wallet'
}
// Чтобы добраться до баланса: user.Wallet.Balance


// 2. ВСТРАИВАНИЕ (Embedding):
type SuperUser struct {
    Wallet // ИМЕНИ НЕТ! Просто указали тип структуры
}
// Магия: user.Balance (поле само всплыло наверх!)
```

---

## 2. Продвижение методов (Promoted Methods)

Самая мощная фишка встраивания: **все методы встроенной структуры тоже всплывают наверх!**

Давай соберем систему ролей для бота:

```go
package main

import "fmt"

// Базовая "деталь LEGO": Обычный пользователь
type User struct {
    Username string
    Email    string
}

// Метод обычного пользователя
func (u *User) Login() {
    fmt.Printf("Пользователь %s вошел в систему\n", u.Username)
}

// Собираем Админа: Админ — это User + права модератора
type Admin struct {
    User       // ВСТРАИВАНИЕ! (Админ получает все поля и методы User)
    SuperPower string
}

func main() {
    // Создаем админа:
    admin := Admin{
        User: User{
            Username: "boss_alex",
            Email:    "alex@crypto.com",
        },
        SuperPower: "Бан навсегда",
    }

    // 1. Поля всплыли наверх (не нужно писать admin.User.Username):
    fmt.Println("Имя админа:", admin.Username)

    // 2. Методы тоже всплыли наверх!
    // У Admin нет своего метода Login(), но он берет его у встроенного User:
    admin.Login() // Выведет: Пользователь boss_alex вошел в систему
}
```

## 3. Переопределение методов (Shadowing)

Что если мы хотим, чтобы у Админа метод `Login()` работал по-особенному (например, с проверкой двухфакторки)?

Мы просто пишем для `Admin` свой собственный метод `Login()`. Он **перекроет (затенит)** базовый метод:

```go
// Переопределяем Login для Admin
func (a *Admin) Login() {
    fmt.Printf("⚠️ АДМИНИСТРАТОР %s вошел с повышенными правами!\n", a.Username)
}

func main() {
    admin := Admin{
        User: User{Username: "boss_alex"},
    }

    // Вызовется переопределенный метод админа:
    admin.Login()

    // Но если очень надо, можно вызвать и старый базовый метод:
    admin.User.Login()
}
```

## 4. Встраивание нескольких структур (Множественное "наследование")

Ты можешь встроить в одну структуру сколько угодно других «деталей»:

```go
type SecuritySystem struct {
    Has2FA bool
}

type BankAccount struct {
    Balance float64
}

// VIP-клиент собран из двух разных сущностей:
type VIPUser struct {
    SecuritySystem // встроен раз
    BankAccount    // встроен два
    Tier           int
}
```
*Теперь у `VIPUser` есть и `.Has2FA`, и `.Balance`, и `.Tier`!*
